# Morning Report Hub Ver.0.2

## Ver.0.1から更新する方へ（最初にお読みください）

**Google OAuth Client IDは、config.jsのGOOGLE_CLIENT_IDに設定済みです。実際のGoogle認証・Drive接続テストはまだ未実施です。** この作業では新版の公開は行っていません。Google Driveに接続しなくても、朝の入力・端末内保存・レポート・履歴・JSONバックアップは使えます。

**次に行う操作は1つだけ：既存のスマートフォンのVer.0.1で「設定」→「バックアップを書き出す」を実行し、JSONをスマホ内に保管してください。開発PCへ送る必要はありません。**

実データが入っているスマホで「全削除」「サイトデータを消去」「ブラウザの初期化」は行わないでください。以下にある架空データでの初回確認・削除手順は、新規の空のテスト環境だけが対象です。

### データを引き継ぐ仕組み

- 本体の保存キーは **`morning-report-hub.v1`** のままです。
- 本体・従来のJSONバックアップとも **`version: 1`** を維持します。
- `records`、`settings`、`draft`、`draftDay`を維持し、起動だけで保存内容を書き換えません。起動時の検査で既存の記録・設定を変換しないようにしています。
- 通常の保存先は引き続きlocalStorageです。Drive未接続、オフライン、認証切れ、同期失敗でもローカル保存は独立して使えます。
- 同期情報は別キー **`morning-report-hub.sync.v1`** に保存します。ファイルID、最後に一致したハッシュ、同期日時、ローカル更新日時、公開Client IDのみです。
- 上書き前の安全コピーは別キー **`morning-report-hub.sync-safety.v1`** に保存します。既存の本体データ構造には混ぜません。
- 更新先の配信元（HTTPSのホスト名など）やブラウザを変えると別の保存領域になります。現在の公開先・ブラウザ・ホーム画面からの起動方法を維持してください。

### Google Driveへ送るもの・送らないもの

接続を許可した場合だけ、`version`、`records`、`settings`を、アプリ専用領域 **appDataFolder** の **morning-report-hub-sync.json** に保存します。通常のマイドライブにはファイルを作りません。

`draft`・`draftDay`は送信せず、Driveから記録を取り込むときも端末側の値を保持します。画面で編集中の未保存の固定依頼文も、Drive反映で勝手に消さないようにしています。Drive同期対象になるのは、保存ボタンで保存した依頼文です。

権限は **`https://www.googleapis.com/auth/drive.appdata`だけ**です。アクセストークンはページを開いている間のメモリだけに置き、localStorage・sessionStorage・IndexedDB・JSON・ログには保存しません。Client secretとrefresh tokenは使いません。

### 同期の進み方

1. まず端末内への保存を完了します。
2. 保存対象のキー順を再帰的にそろえ、Web Crypto APIのSHA-256で内容を比較します。
3. 端末とDriveが同じなら同期済みにします。
4. 最後に同期した内容から端末だけ変わった場合は、Driveへ反映します。
5. Driveだけ変わった場合は、端末の下書きを保持して反映します。
6. 両方が変わった場合・初回で内容が違う場合は、勝手に採用せず選択画面を出します。

削除も記録全体の変更として比較します。個別の日付を自動マージしません。Driveの記録・依頼文がどちらも空で、端末側に内容がある場合は、端末への上書きを停止します。

Driveの検索が正常に完了して0件だった場合に限り「まだデータがありません」と表示し、初回バックアップの確認を求めます。通信エラー、401・403などのAPIエラー、形式不正を「データなし」と扱いません。同名ファイルが複数ある場合も、勝手に選ばず停止します。

### 自動同期・手動同期・解除

- 有効なトークンがメモリにあり、オンラインの場合、記録・保存済み設定の変更から約3秒後に自動同期を試します。連続変更はまとめます。
- 下書きだけの変更ではDrive通信をしません。
- 通信が復帰したときも、有効なトークンがあれば同期を試します。
- ページを閉じた後、認証期限切れ、未接続の場合は「接続」または「今すぐ同期」を押して認証します。勝手にOAuth画面を開きません。
- 初めて接続ボタンを押した際はGoogle公式ライブラリを読み込みます。「認証の準備ができました」と出たら、もう一度接続ボタンを押してください。これは認証ポップアップを確実にユーザー操作から開くためです。
- 競合のキャンセルやデータ不正で停止した場合は、内容を確認して「今すぐ同期」で再開します。通信失敗は連続再試行せず、次の記録変更・通信復帰・手動同期で再試行します。
- 接続解除はメモリのトークンと同期管理情報だけを破棄します。端末の記録・Driveのファイル・安全コピーは削除しません。Googleアカウント自体の権限取り消しは実行しません。

### 競合と安全コピー

競合画面には、端末とDriveの記録件数、Drive更新日時、最後の正常同期日時を表示します。「端末を使用」「Driveを使用」「キャンセル」から選び、上書きする場合はもう一度確認します。

Driveから端末へ反映する前、または競合で端末の内容をDriveへ採用する前に、上書きされる側をこの端末に安全コピーとして残します。同じ内容の重複を除き最大20件で、自動削除はしません。容量不足や上限で安全コピーを保存できない場合は、上書きせず停止します。

設定の「上書き前の安全コピー」でコピーを選んで書き出せます。ファイルは従来のJSONバックアップ形式なので、既存の「バックアップを読み込む」から復元できます。ただし復元は全置き換えです。回復作業中の自動同期を避けるため、復元前にはDrive接続を解除してください。安全コピーにも個人データが含まれます。開発PCへ送らず保管してください。

### 同時編集への保護

確認後に端末・Driveの内容をもう一度比較します。端末側が変わっていたら上書きせず停止します。別タブで保存領域が変わった場合も、古い画面からの保存・同期を停止します。

Drive更新では取得したETagを `If-Match` に付け、比較した版に対する条件付き更新を試みます。更新競合（412）、ETagが取得できない場合、送信後の一致を確認できない場合は同期成功にしません。**実際のDriveでETagがブラウザに公開されることと、条件付き更新の動作は、Client ID設定後の接続試験で確認が必要です。** 取得できない環境では、安全優先で上書きを停止し、無条件更新へ切り替えません。

複数端末が初回作成を全く同時に行う競合では、同名ファイルが複数できる可能性があります。検出したら双方を残して停止します。実接続の確認では初回作成を1端末ずつ行ってください。

### Google Cloud側の設定・確認項目

Google OAuth Client IDのコードへの設定は完了しています。Google Cloud側の設定内容はこの作業では確認していません。実接続テストに向けた確認項目は次のとおりです。

- 使用するGoogle Cloudプロジェクトと、Google Drive APIの有効化。
- OAuth同意画面のアプリ情報・対象ユーザー。テスト公開の場合は利用するGoogleアカウントをテストユーザーとして設定。
- **ウェブアプリケーション**のOAuth Client ID。
- 承認済みJavaScript生成元として、現在のGitHub Pagesの配信元。例は `https://＜ユーザー名＞.github.io` で、リポジトリのパスは含めません。
- 使用する権限は `drive.appdata`のみ。バックエンドやClient secret、refresh tokenは不要です。
- 公開Client IDは **config.js の GOOGLE_CLIENT_ID** に設定済みです。

Token Modelのポップアップ方式を使用します。認証用サーバーやコールバックページは追加していません。GitHub Pagesのレスポンスヘッダーは、このコードから変更できません。COOPをHTMLのmetaタグで設定する変更もしていません。配信元が厳しい `Cross-Origin-Opener-Policy: same-origin` を設定している場合は、認証ポップアップに影響し得るため、後の実接続試験で確認します。

## 2. PCで開いて確認する

1. エクスプローラーでデスクトップの `morning-report-hub` フォルダーを開きます。
2. `index.html` をダブルクリックします。EdgeやChromeなどのブラウザで開いてください。
3. 日付以外が空で、体重履歴にも記録がないことを確認します。
4. PCには実際の体重や個人的な固定依頼文を入力しないでください。入力を確認するときは架空の値だけを使ってください。
5. 試した場合は、最後に「設定」→一番下の「すべてのデータを削除」→確認→再確認で消します。試しに書き出したバックアップも削除してください。

ダブルクリックでの起動にはサーバー・アカウント・ネット接続は不要です。ただしローカルファイルの保存や自動コピーの許可はブラウザによって異なります。コピーできない場合は文章を長押し・選択してコピーできます。スマホでの継続利用には、後述するHTTPSでの利用をおすすめします。

## 3. 毎朝の使い方

1. **朝の入力**を開き、日付・体重・睡眠・疲労などを入力します。
2. 問題がなければ「体調系を問題なしに設定」でまとめて選べます。体重・睡眠・疲労・その他の体調の自由記述は変わりません。
3. 今日の予定を入力します。食事予定は折りたたみを開き、決まっているものだけ入力します。
4. **朝レポートを生成**を押します。この日付の記録が保存され、3種類の文章が表示されます。
5. 各カードの**コピー**を押して、ChatGPTの対応するChatに貼り付けます。アプリからChatGPTへ自動送信はしません。

日付と体重以外は未入力でも生成できます。入力されていない情報は推測しません。各選択ボタンはもう一度押すと未選択に戻せます。筋肉痛は未選択と0を区別します。

日付は `YYYY/MM/DD` です。スマホでは8桁の数字だけを入力しても、区切りを自動で入れます。分割睡眠は時間と分から合計します。追加睡眠を入力した場合は、主睡眠も入力してください。

入力途中もブラウザ内に保存します。同じ日に開き直すと再開できます。翌日に開くと今日の日付の空フォームになります。以前の入力途中は「前回の入力途中を再開」で戻せます。新しく入力すると、入力途中の保存は新しい内容に置き換わります。日付ごとの保存済み記録は残ります。

日付を手で変えても、フォーム内のほかの値は変わりません。既存の日付なら「この日の保存済み記録を読み込む」で呼び出せます。生成・保存時に同じ日の記録があれば確認後に更新します。

**入力フォームだけクリア**は履歴・設定を消しません。**この日の記録を削除**は選択日だけを削除します。入力を変えると古いレポートは隠れるため、再生成してください。

## 4. 過去の体重と週平均

「体重履歴」で日付と体重を入力して「体重を保存」を押します。過去2〜3週間分を繰り返し登録できます。同じ日付の体重を保存すると、体調などを残して体重だけ更新します。一覧から編集・削除もできます。「朝の入力へ」は保存済みの体調も含めてフォームへ読み込みます。

週平均の基準日は「朝の入力」の日付です。

- 今週：月曜日から基準日まで。
- 先週・前々週：それぞれ月曜日から日曜日まで。
- 記録がある日だけで計算し、1日1件として扱います。
- 平均は小数第2位まで四捨五入します。
- 記録がない週は「データなし」と表示します。
- 体重推移も基準日までを表示し、それより後の記録は混ぜません。

「単日の体重だけで食事方針を変更しない」という依頼文は、対象の3週間のうち**2週間以上に、それぞれ3日以上の記録がある場合**に付けます。この条件はVer.0.1の表示ルールで、医学的な評価基準ではありません。アプリは食事量やトレーニングの可否を判断しません。

## 5. 固定依頼文・バックアップ

固定依頼文は「設定」でスマホから入力し、**固定依頼文を保存**を押してください。初期値は空です。保存した場合だけ各レポートの末尾に追加されます。

バックアップは「設定」→**バックアップを書き出す**。全記録・保存済み固定依頼文・入力途中がJSONファイルになります。保存先はスマホのダウンロードやファイルアプリで確認してください。編集した固定依頼文は先に保存してください。

復元は「設定」→**バックアップを読み込む**→JSONを選択→表示された件数・期間・置き換え内容を確認→承認です。現在のデータとの結合ではなく**全置き換え**です。キャンセルすれば変更されません。形式や数値が不正なファイルでは、既存の記録を変更しません。

JSONには個人データがそのまま入ります。開発PCへコピーせず、スマホ上で安全に保管してください。ファイル保存先のクラウド同期設定はOS側の設定に従います。Ver.0.2のGoogle Drive同期は任意です。接続を許可するまで同期は行いません。

## 6. スマートフォンで使うための公開手順

**今回の更新版は未公開です。外部サービスへの登録・アップロードも行っていません。** 既存のGitHub Pagesを使用中なら、公開先は変更せず引き続き使用してください。以下は新規公開の場合の参考手順です。PCの `file:` の場所をスマホに送っても開けません。

スマホで安定して開くには、個人データを含まないアプリの8ファイルをHTTPSの静的サイトとして配置し、そのURLをスマホで開きます。最初のダウンロードには通信が必要ですが、「オフライン準備完了」と表示された後は、アプリの起動・入力・保存・生成をオフラインで行えます。ChatGPTへの貼り付け後の利用にはChatGPT側の通信が必要です。

公開先をまだ持っていない場合の例がGitHub Pagesです。公開リポジトリならGitHub Freeで利用できます。以下はご自身が公開を選ぶ場合の手順で、今回そのサービスを追加したわけではありません。

1. [GitHub](https://github.com/)でアカウントを作り、ログインします。
2. 右上の「＋」→「New repository」を選びます。
3. Repository nameを `morning-report-hub`、公開範囲を **Public** にして「Create repository」を押します。ここに置くコードは誰でも閲覧できます。
4. 空のリポジトリの「uploading an existing file」、または「Add file」→「Upload files」を開きます。
5. **index.html / styles.css / app.js / config.js / google-drive-sync.js / sw.js / manifest.webmanifest / icon.svg の8ファイルだけ**をドラッグします。フォルダーの中に入れず、その階層に直接置きます。バックアップJSONは絶対にアップロードしないでください。
6. 「Commit changes」で保存します。
7. 「Settings」→左メニューの「Pages」→「Build and deployment」で、Sourceを「Deploy from a branch」にします。
8. Branchを **main**、フォルダーを **/(root)** にして「Save」を押します。
9. 公開処理が終わるとPages画面に表示されるサイトURLを、スマホで開きます。反映には数分かかる場合があります。

GitHubの公式案内：[GitHub Pagesを始める](https://docs.github.com/en/pages/getting-started-with-github-pages)、[初心者向け設定手順](https://github.blog/developer-skills/github/github-for-beginners-getting-started-with-github-pages/)。画面名が変わっている場合は公式案内を確認してください。

公開サイトの配信元には、初回の画面取得などに伴う通常のアクセス情報（IPアドレス等）が届き得ます。Drive未接続時は体重・体調・固定依頼文をアプリから送信しません。Drive接続中は、記録と保存済み固定依頼文をGoogleへ同期します。配信元へのアクセス自体も避けたい場合は公開せずローカルファイルで利用しますが、スマホのファイル起動は機種・ブラウザによる制限があり、実機確認が必要です。

## 7. ホーム画面へ追加して使う

実際の記録を入力する前に、利用するブラウザ・URL・起動方法を決めてください。

- **iPhone**：Safariで公開URLを開く→共有メニュー→「ホーム画面に追加」→表示される場合は「Webアプリとして開く」をオン→追加。[Apple公式手順](https://support.apple.com/guide/iphone/iphea86e5236/ios)
- **Android**：Chromeで公開URLを開く→右上のメニュー→「ホーム画面に追加」または「アプリをインストール」→画面の案内に従う。[Google公式手順](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=ja)

追加したアイコンから起動して「オフライン準備完了」を確認します。この起動方法を毎日使ってください。通常のブラウザ表示とホーム画面アプリ、別のブラウザ、別URLでは記録の保存領域が異なる場合があります。移行前にはバックアップを作ってください。

実データがない新規のテスト環境に限り、架空の入力で次を確認してください。既存の実データ入りスマホでは、以下の削除手順を実行しないでください。

1. 体重を入れ、生成すると3カードが出る。
2. 各コピーでメモアプリ等に正しい文章を貼り付けられる。
3. 空の食事予定や前日のトレーニングが文章に出ない。
4. アプリを閉じて開き直しても履歴が残る。
5. バックアップを書き出し、確認画面を経て復元できる。
6. オフライン準備完了後、機内モードにしてアプリを開き直せる。
7. 確認を終えたら「設定」→「すべてのデータを削除」を2回の確認で実行し、架空のバックアップも削除する。
8. スマホで実際の入力を始める。

ブラウザが保存領域やキャッシュを消去した場合は、記録の復元にバックアップ、アプリの再取得に通信が必要です。プライベート／シークレットモードは使わず、定期的にバックアップしてください。

## 8. プライバシーと確認済みの範囲

- バックエンド、外部DB、広告、アクセス解析、外部フォントはありません。任意のDrive接続に限り、Google Identity Services公式JavaScriptとDrive APIを使います。
- 記録をURLや画面キャッシュに入れません。Drive接続中の同期ではGoogleへの通信本文に記録・保存済み固定依頼文が入ります。
- 記録の保存先は、このブラウザのlocalStorageにある本アプリ専用キーです。Driveに接続した場合は、保存済み記録と固定依頼文を端末間で同期できます。
- 保存値は暗号化していません。端末のロックやブラウザのアクセス管理をご自身で行ってください。
- 画面に表示するユーザー入力はHTMLとして実行せず、文字として扱います。
- オフライン用キャッシュに入れるのは上記の静的なアプリファイルだけです。ブラウザは静的ファイルやアプリ更新の確認のために配信元へアクセスする場合があります。
- 明示的な全削除操作はこの端末の本体データと同期管理情報を削除し、接続を解除します。Drive上の記録と安全コピーは残ります。他のアプリの保存データや、自分で書き出したJSONは削除しません。オフライン用の画面ファイルは残ります。
- 開発時は架空データのみを隔離した一時ブラウザで使用しました。終了時に保存データを削除し、ブラウザを終了しました。テスト用コード・JSONも納品物に残していません。
- 週平均・年をまたぐ週・分割睡眠・入力チェック・3種類のコピー・保存・履歴編集・削除・バックアップ往復・オフライン再起動を確認しました。
- WindowsのEdgeによる自動確認で、320 / 390 / 768 / 1280px幅の横はみ出しがないことを確認し、390px幅の画面を画像で確認しました。実物のiPhone・Androidでの確認は未実施です。

## 開発者向けメモ

`app.js` 内でデータ処理・文章生成・画面処理を分離しています。前半の純粋関数はNode.jsから読み込めます。アプリの実行にNode.jsは必要ありません。

バックアップの `version` は1、localStorageのキーは `morning-report-hub.v1`。週計算にはローカル日付を使用します。平均は整数化した体重から求め、小数第2位で四捨五入します。

公開後に画面や処理を更新するときは、`sw.js` の `CACHE` 名の末尾を変更し、8ファイルを一緒に再公開してください。ユーザーはオンラインで新しい画面ファイルを取得した後、同じアプリのタブ・ホーム画面アプリをすべて閉じてから開き直してください。旧画面を使用中に新版が割り込まないよう、更新は待機します。localStorageの構造を変更する場合は別途データ移行が必要です。
